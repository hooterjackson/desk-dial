# Floating knob (desktop v5)

Status: **frozen for desktop v5**. Section 9 records the refinements accepted at integration (2026-09-24); where it and an earlier sentence differ, section 9 wins. Desktop v6 amendment (2026-09-25): the `'carousel'` suppression reason in section 4, from CAROUSEL.md section 11. User request (2026-09-24):

> The desktop app should just be the knob face with the LEDs surrounding it, floating over space, with no toolbar. It slides in from the side of the screen when I interact with the physical knob and disappears when I stop. Images and LED ticks must be high resolution.

User decisions:
- **Position:** left edge, vertically centred.
- **Hide delay:** 2.5 s after the last touch.
- **Size:** medium, a ring about 360 px across.
- **Triggers:** physical knob touches only.

Scope. This release changes only the desktop app. It makes no firmware, wire or contract change, so the knob stays on 1.0.0-cc5.3. The simulator and dev launcher (`app.py`) keep today's full window, and all its tests stay valid. Only the installed live app (`standalone.py`) switches to the floating knob.

## 1. Architecture

```
Tk thread (existing, root withdrawn for the whole process)
  runtime.poll() ── note_touch() on physical position/button edges (and the F24 hotkey)
  _poll_once ─┬─ preview_lights.render(...) every tick (cheap; keeps decay and flashes continuous)
              ├─ if overlay.wants_frames: LCD at overlay.lcd_px (cached), ring colours → overlay.submit(scene)
              └─ if touch_seq changed: overlay.touch()
Overlay thread "NanoD-overlay" (new; owns the HWND, DC, DIB and animation)
  layered popup window  ←  KnobFace compositor (plate + ring sprites + LCD)  →  UpdateLayeredWindow
```

- **The root stays.** The Tk root stays withdrawn for the process lifetime. It still owns the F24 hotkey subclass, parents the picker, and hosts every `after()` timer. It is never restyled.
- **Thread boundary** (the rule that prevents the documented crash, `windows.py:10-22`):
  - The overlay thread is the only thread that touches the overlay's HWND, DC and DIB.
  - The Tk thread only calls `PostMessageW`, and hands frames over through a lock-protected, newest-wins slot.
  - Nothing on the overlay thread touches tkinter.
  - Nothing ever `SendMessage`s the overlay, or calls `SetWindowPos` or `ShowWindow` on it from another thread.

## 2. Look

The design px below are Knob Face px.

**Knob face** (the Knob Face design, painted in this order):
1. **Plate:** a dark circular backplate, `#111111` at alpha 235, radius 154 design px, with a soft drop shadow (black, alpha ≤ 90, blur ≈ 10 design px, offset 0,3). It keeps the LEDs readable on light wallpapers; it is a deliberate addition to Knob Face.
2. **Ring:** 60 segments, 4×10 design px, centres at radius 138, rotated i·6° from 12 o'clock.
   - Unlit: `#1f1f1f`.
   - Lit colour: from the existing colour model (`ring_display` / `ring_palette` / `optical_alpha` / `led_source`), unchanged.
   - Glow: lit segments get a glow per Knob Face (alpha ≤ 0.7·level). The glow is clipped by the disc, because the disc is painted after the ring.
3. **Disc:** radius 126 design px, `#0a0a0a`, with a 1 px `#262626` inner edge.
4. **LCD:** the 240 design px LCD, centred, drawn by `lcd_preview.render_lcd` at the overlay's scale. It is never upscaled from 240.

**No button strip**, no text panel and no chrome. The LCD already shows the button legends.

**Scale.** The ring's outer diameter (the outer segment ends, 2 × 143 = 286 design px) is **360 logical px**. So `S = 360/286` design→logical, and `px = logical × monitorDPI/96`. The window box is the plate plus the shadow margin, rounded up to even pixels.

**Everything is anti-aliased at physical pixels:**
- Segment and plate masks are drawn 4× supersampled, then LANCZOS-downscaled.
- They are built once per physical size, and again when the DPI changes.
- Frames are composed by pasting cached sprites (Pillow `paste(image, box, mask)`, never `paste(colour, box, mask)`, which is straight-alpha and makes halos). Then `tobytes('raw','BGRa')` produces premultiplied BGRA.

**High-resolution sources** (for `scale > 1` only; `scale == 1` stays byte-identical, section 3):
- **Covers:** `ArtworkResult.hires_jpeg` holds the source fitted to 480 px with the continuous scrim80 composite, as a quality-90 JPEG. It is built in the same `prepare` pass and keyed the same way as `jpeg_key`/`key`. It is used when the overlay's LCD is larger than 240 px; otherwise the existing 240 image is used.
- **Footer and idle icons:** `@2x` and `@3x` PNG masks next to the shipped ones in `assets/lcd-icons`. They are generated by a **PNG-only** mode of the icon exporter, which must never touch firmware `cc_icons.cpp/.h`, or by an exact PIL stroker of the knob-model icon paths. For fractional scales, the nearest export at or above the scale is downsampled.
- **App icons:** IconWorker keeps a 128 px RGBA copy, taken from `SHGetImageList(SHIL_JUMBO)` or `IShellItemImageFactory::GetImage(…, SIIGBF_ICONONLY)` on its existing COM thread, next to the 32 px payload icon.
  - Ring accents stay computed from the current 32 px source.
  - The knob still gets the 2048-byte payload.
  - UWP apps may now get a hi-res icon on the desktop only. The knob keeps its letter tile for them (deviation 9 is unchanged).

**Mirror promise.** At `scale > 1` the overlay draws the same layout and the same pixels-per-design as the knob, from higher-fidelity sources. The docs must say "same layout, higher fidelity", not "pixel-identical".

## 4. Overlay window (Win32, `control_center/overlay.py`)

**Window.**
- Class `NanoD.KnobOverlay`:
  - a module-level WNDPROC thunk that is never freed;
  - `hInstance = GetModuleHandleW(None)`;
  - `ERROR_CLASS_ALREADY_EXISTS` (1410) is tolerated.
- `CreateWindowExW(WS_EX_LAYERED|WS_EX_TOPMOST|WS_EX_TOOLWINDOW|WS_EX_NOACTIVATE|WS_EX_TRANSPARENT (0x080800A8), …, WS_POPUP, …, parent NULL)`. It is never `WS_VISIBLE` at creation.
- **WNDPROC:**
  - `WM_MOUSEACTIVATE` returns `MA_NOACTIVATE`;
  - `WM_NCHITTEST` returns `HTTRANSPARENT`;
  - `WM_DISPLAYCHANGE`, `WM_SETTINGCHANGE`(`SPI_SETWORKAREA`), `WM_DPICHANGED` and `WM_DWMCOMPOSITIONCHANGED` mark the geometry dirty;
  - `WM_POWERBROADCAST` suspend and `WM_ENDSESSION` hide immediately;
  - every handler is wrapped in `try/except BaseException`, falling back to `DefWindowProcW`, declared with an `LPARAM` return type.

**Thread start.**
1. `SetThreadDpiAwarenessContext(-4)`, verified.
2. `PeekMessageW` to create the queue.
3. Register the class, then create the window, the memory DC and the DIB.
4. Signal a `threading.Event`. The Tk side waits at most 2 s.

If creation fails, the overlay is disabled, the reason is logged, the app keeps running, and the tray still works.

**Presenting a frame.**
- The DIB is 32-bit top-down, **twice the window width**; the right half stays transparent.
- `UpdateLayeredWindow(hwnd, NULL, &ptDst, &size, hdcMem, &ptSrc, 0, BLENDFUNCTION(AC_SRC_OVER,0,alpha,AC_SRC_ALPHA), ULW_ALPHA)`.
- `SetLayeredWindowAttributes` is never called on this window.
- Every BOOL result is checked, and failures are logged with a rate limit.

**Placement.**
- The primary monitor comes from `MonitorFromPoint((0,0), MONITOR_DEFAULTTOPRIMARY)`, then `rcWork` and `GetDpiForMonitor` (effective).
- `x = work.left + 24 logical px`, `y = work.top + (work.h − H)//2`.
- Geometry is recomputed on every slide-in and whenever it is marked dirty. The DPI-dependent sprites are rebuilt when the physical size changes.

**Slide.**
- The window rectangle stays fixed. The content sits in the left half of the double-width DIB, and `ptSrc.x` animates from `W` (hidden) to `0` (shown), with `SourceConstantAlpha` fading between 0 and 255. The content therefore emerges from the left screen edge, never appears on a monitor to the left, and never straddles monitors.
- Slide-in takes 220 ms with ease-out cubic; slide-out takes 260 ms with ease-in cubic. A touch during slide-out reverses from the current progress, with no jump.
- While animating, the loop drains messages, steps the animation from `time.perf_counter()`, then calls `DwmFlush()` for vsync pacing. If `DwmFlush` fails, it uses `MsgWaitForMultipleObjectsEx(…, 8 ms, QS_ALLINPUT, MWMO_INPUTAVAILABLE)`. It never busy-spins. When idle, it blocks in `GetMessageW`.

**Show and hide.**
- The first frame is presented while hidden. The window is then shown with `SetWindowPos(HWND_TOPMOST, …, SWP_NOACTIVATE|SWP_NOOWNERZORDER|SWP_SHOWWINDOW)` or `ShowWindow(SW_SHOWNA)`, and `HWND_TOPMOST` is re-asserted on every slide-in.
- After the slide-out it calls `ShowWindow(SW_HIDE)`.
- These are never used on the overlay: `SW_SHOW`, `SW_SHOWNORMAL`, `SW_SHOWDEFAULT`, `SetForegroundWindow`, `SetActiveWindow`, `BringWindowToTop`.

**State machine.** It is platform-neutral and unit-tested with a fake backend and a fake clock.
- The states are `hidden → in → shown → out → hidden`.
- `touch()` from `hidden` or `out` goes to `in`, and every `touch()` sets `deadline = now + 2.5 s`.
- In `shown`, once `now ≥ deadline` it goes to `out`.
- `peek(seconds)` is a touch with its own duration, used by the tray "Show knob" item.
- `set_suppressed(True)` hides at once, with a slide-out, and ignores touches while it holds. It holds:
  - while the Windows carousel (desktop v6) is open, reason `'carousel'`: from its open to the end of its Switch or Cancel exit, wherever the knob is and with either background. Touches meanwhile do not slide the knob in, and it comes back by its normal touch rules. See CAROUSEL.md section 11, which replaced the carousel's pane-overlap test with this reason;
  - while a Windows picker that publishes no `rect` (a Tk window, as the v5 grid was) overlaps the overlay's rectangle, reason `'picker'`, and only while the controller is in Windows mode;
  - during D3D full-screen or presentation mode (`SHQueryUserNotificationState` 3/4), which is checked at each slide-in;
  - while the knob is disconnected, reason `'disconnected'`.

**Frame hand-off (newest wins).**
- `submit(scene)` stores an immutable scene: the LCD key, the LCD RGBA image at `lcd_px` (never mutated after hand-off), 60 ring colours as `0xRRGGBB` plus alpha level, and flags. It then posts `WM_APP+1` only if no post is pending. A failed post clears the pending flag.
- The overlay thread composes the knob face with `KnobFace` and uploads it. It skips identical scenes.
- **`wants_frames`** is a plain bool, true while the state is not `hidden` (and from an accepted touch on, see 9.3). The Tk side renders and submits only when it is true.
- **Frame rate:** at most one submit per UI tick (25 ms), and only when the ring colours or the LCD key changed.

**Cleanup.** Everything runs on the overlay thread, in this order:
1. `KillTimer`.
2. `SelectObject` back to the old bitmap.
3. `DeleteObject` the DIB. No memmove after this.
4. `DeleteDC`.
5. `DestroyWindow`, whose `WM_DESTROY` calls `PostQuitMessage`.
6. Leave the loop and `UnregisterClassW`.

The Tk side's `close()` posts `WM_APP+3`, then joins the thread with a 1 s timeout. `close()` is called from `ControlCenterApp.close` and from standalone's `finally`, before `root.destroy()`.

**Diagnostics.** `overlay.metrics()` returns:
- state;
- DPI, window px and lcd px;
- frames presented and ULW failures;
- the last error;
- `GetGuiResources` GDI and USER counts.

These are written to `status.json` under `overlay`.

## 5. Touch hook (`runtime.py`)

- `Runtime.note_touch(kind)` records `touch_seq += 1`, `last_touch = time.monotonic()` and `last_touch_kind`. It only records: no Tk calls, no window calls. It is safe inside the `WM_HOTKEY` path.
- **Call sites:**
  - `_device_events` `position` branch, first thing;
  - `button` branch, after the key-up and index filters, before the probe and Windows-button (logical 2) skips;
  - `Runtime.hotkey()` right after its guard.
- **Not touches:** frames, heartbeats, Sonos state, external volume, lease, reconnect, media, simulated input.
- The dev/simulator mode may call `note_touch('sim')` from its input handlers, but it has no overlay.
- Known limit, documented and not fixed here: turning into an end stop sends no serial event, so that gesture alone does not summon the knob.

## 6. App integration (`ui.py`, `standalone.py`)

**`ControlCenterApp(…, chrome=False)`.** Only standalone live uses it; the default stays `True`.
- It skips `build()`, the header, the right panel, the footer, the canvas, `_fit_window` and the root key bindings.

- The mirror gate `_mirror_visible` becomes `overlay.wants_frames`.
- `preview_lights.render` runs every tick while connected.
- The existing reset-on-reappear happens on the transition out of `hidden` (only when the lights missed ticks, see 9.6).

**Settings (the existing Setup window).**
- In `chrome=False` mode it is not `transient(root)`.
- It is opened through `deiconify()`, `lift()` and `focus_force()`. The tray click grants foreground rights.
- Its content is unchanged.

**Tray menu.** Callbacks only queue request strings for the Tk thread, as today.
1. A disabled status line (the device status, refreshed after each menu action).
2. **Show knob**: the default, triggered by a left click. It peeks the overlay for 2.5 s.
3. **Settings…**
4. **Disconnect knob** / **Connect knob**: a dynamic label.
5. **Quit**

- The tooltip shows the device status, set only when it changes, at most 127 characters.
- `controller.notice` errors go to `icon.notify(…)` balloons, rate-limited. The notice is not cleared (see 9.5).

**Entry points.**
- A second launch, or the Start-menu `--show`, opens Settings.
- If the tray fails, Settings opens with added Connect/Disconnect and Quit buttons, so the app is never invisible and unquittable.
- The installed task still starts with `--background`.

**Smoke test (`--smoke-test`, frozen build gate).** It keeps every existing check and replaces `ui_check`'s canvas requirement with an overlay check that:
- renders a knob face with `KnobFace` at 100 % and 200 % DPI to PIL;
- runs `render_lcd` at `scale > 1` with a hi-res cover and icon;
- creates the overlay window **hidden**, builds the DIB, calls `UpdateLayeredWindow` on the hidden window, then destroys it and unregisters the class, asserting that the GDI/USER counts return to baseline.

It never shows a window and runs before the single-instance mutex.

## 9. Recorded refinements (integration, 2026-09-24)

These were accepted when the render, overlay and integration tracks were merged. Each one keeps the intent of the section it refines; the code and tests follow this section.

1. **Touch deadline** (section 4): every `touch()`/`peek(s)` sets `deadline = call time + s`, literally, so a touch can shorten a longer peek. All callers use 2.5 s. No deviation; recorded for clarity.
2. **First frame** (section 4): a slide-in from `hidden` is armed until a scene submitted at or after the touch arrives, for at most 100 ms, so the frame presented while hidden is the current face, not a stale one. `ui.py` submits before `touch()` on the touch tick, so this adds about 0 ms to a touch and at most one 25 ms UI tick to a tray **Show knob**.
3. **`wants_frames`** (section 4): it turns true as soon as `touch()`/`peek()` is accepted, one step before the overlay thread leaves `hidden`, so the Tk side renders the first frame on its next tick. It falls back to "state is not `hidden`" once the overlay thread has taken the touch; a touch the thread ignores (full screen, suppression) clears it.
4. **Suppression hand-off** (section 4): `set_suppressed` travels as its own `WM_APP+4` (`WM_APP+1` frame, `+2` touch, `+3` stop). The overlay thread also re-reads the reasons on every wake-up, so a hold or release whose post was lost is applied on the next touch, frame or timer. A message loop that ends without `close()` disables the overlay (state `disabled`, reason in `last_error`).
5. **Tray notices** (section 6): each new `controller.notice` becomes one rate-limited balloon. The notice is **not** cleared: it keeps its v4 lifetime, so the knob keeps showing "Last action failed" until the next action. Clearing it would have cut that knob line to one tray tick (about 100 ms). If the tray failed, the fallback Settings window shows the notice; a click dismisses it (`clear_notice()`).
6. **Lights on reappear** (section 6): on the transition out of `hidden`, PreviewLights is reset only if it skipped ticks (the knob was disconnected). While connected it runs every tick (section 1), so it is never stale, and the flash of the touch that summoned the knob is kept.
7. **Hi-res app icons** (section 2): only `IconWorker(hires=True)` makes the 128 px copies, and only standalone's `chrome=False` app uses it; `app.py` and `--check-music` keep cc5.3's worker. The worker first delivers every 32 px icon and accent of a snapshot (knob payload and ring accent timing as in cc5.3), then each 128 px copy as a later `HiresIcon` result, skipping snapshots already superseded. The runtime keeps the copy next to the 32 px icon without re-sending payloads.
   - **Match-only rule.** A 128 px copy is made only when the window's own 32 px icon is the one the executable's shell icon draws (`icon_matches`, `windows.py`): the floating knob must never show a different icon than the knob does. A window whose icon differs from its exe's (File Explorer folders, windows with a profile or document icon) gets no copy, and `render_lcd` fills the 32 design px tile from its 32 px icon with a LANCZOS upscale (about 1.26× at 100 %, 2.5× at 200 %). This is the one place where the floating knob may show an upscaled source; it is accepted for v5. A later release may try a larger icon of the window itself (`WM_GETICON ICON_BIG` under the process's PMv2 context) before falling back.
8. **Diagnostics** (section 4): `overlay.metrics()` (and so `status.json` `overlay`) also reports `lcd_resizes`, the LCD images the overlay had to fit to `lcd_px` (expected only on the tick after a DPI change), and `face_lcd_resizes`, the current `KnobFace`'s own count. A steady non-zero value means an upscaled LCD, which section 2 forbids.
9. **Imports** (section 2): `knob_face` loads Pillow on first `KnobFace` use, so the colour model, and `ui.py` that re-exports it, import without PIL, as before v5. A broken Pillow only disables the floating knob.
10. **Centring** (section 2): at 150 % and 175 % DPI `lcd_px` is odd. The LCD is pasted at whole pixels, so every layer is drawn about `KnobFace.origin` (`center` + 0.5 px); the window box then grows by 2 px (652 and 760 px).

    - `Install-Desktop.ps1` installs a bundle that is not a recorded rollback only when `%LOCALAPPDATA%\NanoDControlCenter\logs\smoke-test.json` is a pass by that bundle's frozen exe, newer than the exe.
    - All three rollback bundles (v2, v3, v4) are pinned by exe SHA-256.
    - The frozen smoke test also checks every button glyph's @2x and @3x mask (a missing one would otherwise be a silent upscale), and loads the app `.ico` with `LoadImageW`.
